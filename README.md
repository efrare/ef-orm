**ef-ORM** is an async ORM for **Microsoft SQL Server**, inspired by
[SeaORM](https://github.com/SeaQL/sea-orm) (entity traits, fluent queries, derive macros)
and [EF Core](https://learn.microsoft.com/en-us/ef/core/) (`DbContext`, change tracking,
unit of work, migrations). It is built from scratch on top of the
[Tiberius](https://github.com/prisma/tiberius) TDS driver, with a strict layered
architecture where only one crate speaks SQL and only one speaks TDS.

> **Status: 0.0.1 (pre-alpha).** Everything below is implemented and exercised
> end-to-end against SQL Server, but the API is not frozen yet.

## Why ef-ORM?

### SQL Server as a first-class citizen

Not a bolted-on dialect. T-SQL specifics are designed in from day one:
`OFFSET … FETCH` pagination, `OUTPUT INSERTED.*` / `OUTPUT DELETED.*`,
`IDENTITY` keys, `NVARCHAR`, `UNIQUEIDENTIFIER`, `DATETIME2` and
`DECIMAL`, with snapshot tests pinning every generated statement.

### Change tracking, the EF Core way

Reads snapshot their rows; writes are staged and flushed as **one unit of work**.
`UPDATE`/`DELETE` carry the original values in their `WHERE`, so a concurrent
writer turns into `OrmError::Conflict` instead of a silent lost update.

```rust
#[derive(Entity, Model, Debug)]
#[orm(table = "users")]
struct User {
    #[orm(primary_key, auto)]
    id: i32,
    name: String,
    email: String,
}

// insert: the model moves in, the key comes back after the commit
let ticket = ctx.dbset::<User>().insert(user);
ctx.save_changes().await?;
let mut user = ticket.resolve()?;

// update: only the diff is sent, guarded by the original values
user.email = "ada@example.com".into();
ctx.dbset::<User>().update(&user)?;
ctx.save_changes().await?; // one transaction; Conflict on concurrent edits
```

### Fluent, typed queries

Column references are generated by `#[derive(Entity)]`, so typos do not compile
and `like` only exists on text columns.

```rust
let adults = ctx
    .dbset::<User>()
    .select()
    .filter(|c| c.age.ge(18).and(c.name.like("A%")))
    .order_by(User::columns().name, OrderDir::Asc)
    .page(1, 20)
    .all()
    .await?;

// partial projection into any FromRow type
let names = ctx
    .dbset::<User>()
    .select()
    .columns(["name"])
    .all_as::<NameOnly>()
    .await?;
```

### Bulk insert, streaming and raw SQL

```rust
// one BULK INSERT batch (Tiberius BulkLoadRequest)
let inserted = ctx.dbset::<User>().insert_many(&users).await?;

// consume rows incrementally instead of materializing the result set
let mut conn = ctx.checkout().await?;
let mut rows = ctx.dbset::<User>().select().stream(&mut *conn).await?;
while let Some(user) = rows.next().await {
    let user = user?;
    // ...
}

// escape hatch with bound parameters
let total = ctx
    .raw_sql("SELECT COUNT(*) AS [total] FROM [dbo].[users] WHERE [age] > @P1")
    .param(18)
    .fetch_one::<Count>()
    .await?;
```

### Migrations: schema-first or entity-first

Migrations are built from the query AST (never loose SQL strings), recorded in
`__ef_migrations`, and applied one transaction at a time. The engine can also
introspect a live database (`INFORMATION_SCHEMA`), diff it against a target
schema, and scaffold Rust entities.

```rust
fn up(schema: &mut Schema) {
    schema.create_table(
        CreateTable::new("users")
            .column(ColumnDef::new("id", SqlType::Int).identity().primary_key())
            .column(ColumnDef::new("name", SqlType::NVarChar(100)).not_null()),
    );
}
fn down(schema: &mut Schema) {
    schema.drop_table("users");
}

const V1: Migration = Migration::new("001", "create_users", up, down);

let mut migrator = Migrator::new(&mut *conn);
migrator.up(&[V1]).await?;          // DDL + history row, one transaction
migrator.status(&[V1]).await?;      // applied / pending
migrator.down(&[V1], 1).await?;     // rollback
```

```bash
# SQL-file deployments through the CLI (pairs <version>_<name>.up/down.sql)
ef-orm-cli --password "$EF_ORM_DB_PASSWORD" migrate up     --dir migrations
ef-orm-cli --password "$EF_ORM_DB_PASSWORD" migrate status --dir migrations
ef-orm-cli --password "$EF_ORM_DB_PASSWORD" migrate down   --dir migrations --steps 1

# generate #[derive(Entity, Model)] structs from the live schema
ef-orm-cli --password "$EF_ORM_DB_PASSWORD" scaffold --out src/entities.rs
```

## Getting Started

```toml
[dependencies]
ef-orm = { version = "0.1", features = ["with-uuid", "with-chrono", "with-rust_decimal"] }
ef-orm-driver-tds = { version = "0.1", features = ["with-uuid", "with-chrono", "with-rust_decimal"] }
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
```

```rust
use ef_orm::{DbContext, Entity, Model, Pool, PoolOptions};
use ef_orm_driver_tds::{Config, TdsDriver};

#[derive(Entity, Model, Debug)]
#[orm(table = "users")]
struct User {
    #[orm(primary_key, auto)]
    id: i32,
    name: String,
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let config = Config {
        host: "localhost".into(),
        port: 1433,
        database: "master".into(),
        user: "sa".into(),
        password: std::env::var("EF_ORM_DB_PASSWORD")?,
        trust_cert: true,
    };
    let ctx = DbContext::new(Pool::new(TdsDriver::new(config), PoolOptions::default()));

    let ticket = ctx.dbset::<User>().insert(User { id: 0, name: "Ada".into() });
    ctx.save_changes().await?;
    let ada = ticket.resolve()?;
    println!("stored #{} {}", ada.id, ada.name);
    Ok(())
}
```

Credentials are never hard-coded: the examples read `EF_ORM_TEST_DB_*` from the
environment.

## Workspace

The workspace enforces a one-way dependency rule: nothing imports "upwards",
`core` knows no SQL, and only `driver-tds` knows Tiberius.

| Crate | Role |
| --- | --- |
| `ef-orm-core` | Pure domain: `Value`, entity/metadata traits, `OrmError` |
| `ef-orm-query` | Query + DDL AST, `Dialect` and `MssqlDialect` (**the only SQL generator**) |
| `ef-orm-driver` | `Driver`/`Conn`/`Tx`/`Row` traits + connection pool |
| `ef-orm-driver-tds` | The only crate that speaks TDS (Tiberius adapter) |
| `ef-orm` | Facade: `DbContext`, `DbSet`, `ChangeTracker`, unit of work |
| `ef-orm-derive` | Proc-macros: `#[derive(Entity)]`, `#[derive(Model)]` |
| `ef-orm-migrate` | Migration engine, history table, introspection, diff, scaffold |
| `ef-orm-cli` | CLI: `migrate up/down/status`, `scaffold` |

## Feature flags

| Feature | Effect |
| --- | --- |
| `with-uuid` | `UNIQUEIDENTIFIER` ⇄ `uuid::Uuid` |
| `with-chrono` | `DATE`/`DATETIME`/`DATETIME2`/`DATETIMEOFFSET` ⇄ `chrono::NaiveDateTime` |
| `with-rust_decimal` | `DECIMAL`/`NUMERIC` ⇄ `rust_decimal::Decimal` |

Enable the same features on `ef-orm-driver-tds` so Tiberius can read/write them.

## Testing

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Dialect tests are SQL snapshots (no database needed). The examples above are the
integration path and require a reachable SQL Server (`EF_ORM_TEST_DB_*`).
